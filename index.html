How this page got here

deploy passed

Every push to main runs these steps on GitHub Actions.

  1. Validate HTML structure, CV present, no broken local links
  2. Package site/ becomes one release archive, stored as a build artifact
  3. Find the server A dedicated IAM user looks up the EC2 instance
  4. Connect Short-lived SSH key via EC2 Instance Connect, no private key stored in GitHub
  5. Release Unpacked into releases/<commit>, then the current symlink switches
  6. Reload Nginx Config tested with nginx -t before a reload with no downtime
  7. Health check /health and the homepage, from the server and from the internet
  8. Live If any check fails, the previous release comes back automatically

Ubuntu on AWS EC2, served by Nginx. The last five releases are kept for rollback. More on the design

Projects

Work I can walk you through line by line, including the parts I would change.

Zero-downtime deployment for this website

A static site served directly by Nginx on Ubuntu EC2, deployed by GitHub Actions. Each push is checked first, then shipped as a versioned release in its own folder. Going live is a single symlink switch, so visitors never see a half-copied site.

Access stays narrow. The IAM policy only allows sending a temporary SSH key to this one instance, for the ubuntu user. There's no PEM file in the repository. A shell script bootstraps the server in one run, and Nginx adds a health endpoint, caching rules and basic security headers.

Stack: GitHub Actions, AWS EC2, IAM, EC2 Instance Connect, Nginx, Bash, Python

View on GitHub

What I'd change for production

  • GitHub OIDC with an IAM role instead of long-lived access keys.
  • SSM Session Manager or an Instance Connect Endpoint so port 22 doesn't need to be reachable from the internet.
  • HTTPS only with Let's Encrypt and a redirect from HTTP.
  • An approval gate on the production environment, plus uptime alerts.
  • At real traffic, S3 and CloudFront would be cheaper and simpler for a static site.

Pre-commit quality gate

A Git hook that runs before every commit. It formats staged Python files with Black, lints them with Flake8, and blocks the commit if it finds anything that looks like a credential, such as AWS keys, tokens or passwords.

It catches problems on my machine, before they reach CI or the repository history.

Stack: Git hooks, Bash, Black, Flake8
